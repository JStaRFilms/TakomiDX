# [FR-002] Isolated Runtime Execution and Stable Preview Routing

## Labels
`MUS`, `enhancement`, `runtime`

## User Story
As a developer, I want each workspace to run without port collisions and expose a stable local hostname, so that I can open the right preview without guessing ports.

## Proposed Solution

### Overview
Run each workspace in an isolated container-backed runtime and register the resulting target with a local developer edge proxy under a stable `.localhost` hostname.

### Implementation Flow
1. Boot a runtime per workspace with isolated networking and environment variables.
2. Detect or assign the internal preview target.
3. Register a stable route such as `<workspace-slug>.<preview-domain>`.
4. Surface preview health and routing state to Mission Control.

### Technical Approach

```ts
export interface RuntimeHandle {
  workspaceId: string;
  target: string;
  previewHost: string;
  healthStatus: "booting" | "healthy" | "unhealthy";
}

export interface RuntimeExecutor {
  start(workspaceId: string): Promise<RuntimeHandle>;
  stop(workspaceId: string): Promise<void>;
}
```

### Key Considerations
- Users should never need manual port assignment.
- Proxy failures must remain debuggable.
- Routing state should be independent from UI implementation.

## Acceptance Criteria

- [x] Two or more workspaces can boot without port collisions. ✅ Completed with container-backed runtime tests and stable route registration coverage.
- [x] Each workspace gets a stable human-readable preview hostname. ✅ Completed with the Takomi local edge listener serving `*.takomi.localhost`.
- [x] Preview health is visible as structured state. ✅ Completed with distinct route status, proxy status, and upstream health surfaced through `agentd` and Mission Control.
- [x] Route registration failures surface clear diagnostics. ✅ Completed with degraded proxy states and fallback guidance when the local edge listener cannot bind or serve the route.
