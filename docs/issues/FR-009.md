# [FR-009] Stronger MicroVM-Based Isolation

## Labels
`Future`, `enhancement`, `runtime`

## User Story
As a platform-conscious developer, I want higher-trust runtime isolation, so that risky agent actions run in safer execution boundaries.

## Proposed Solution

### Overview
Add a microVM-backed runtime option behind the same workspace abstraction used by the container-backed MVP.

### Implementation Flow
1. Define a pluggable runtime interface.
2. Add a microVM executor implementation.
3. Reuse workspace, routing, auth, and observability surfaces across runtime types.
4. Add configuration for choosing runtime mode per workspace.

### Technical Approach

```ts
export interface WorkspaceRuntimeExecutor {
  kind: "container" | "microvm";
  start(workspaceId: string): Promise<RuntimeHandle>;
  stop(workspaceId: string): Promise<void>;
}
```

### Key Considerations
- Keep the product abstraction stable across runtime types.
- Do not fork the UI or contract model unnecessarily.
- Stronger isolation should not destroy developer ergonomics.

## Acceptance Criteria

- [ ] The runtime interface supports multiple executor implementations.
- [ ] A microVM runtime can be configured without changing workspace semantics.
- [ ] Shared surfaces continue to work across runtime types.
- [ ] The microVM path remains separate from the MVP default.
