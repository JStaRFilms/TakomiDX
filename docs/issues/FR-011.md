# [FR-011] Team Review Queues and Governance

## Labels
`Future`, `enhancement`, `team`

## User Story
As an engineering team, I want shared review queues, approvals, and policy controls, so that agent workflows can be standardized across multiple developers.

## Proposed Solution

### Overview
Build team-facing governance features on top of the workspace and review model once the local single-user control plane is solid.

### Implementation Flow
1. Add shared review queue concepts and reviewer assignment.
2. Add policy packs for approvals, budgets, and risky actions.
3. Add audit-friendly records of who approved what and when.
4. Extend the product from single-user supervision to team workflows.

### Technical Approach

```ts
export interface ReviewQueueItem {
  workspaceId: string;
  reviewerId?: string;
  disposition: "pending" | "approved" | "rejected";
}
```

### Key Considerations
- Team governance should be layered onto a stable single-user model, not built prematurely.
- Auditability matters more than UI complexity in the first team iteration.
- Policy design must avoid blocking legitimate high-velocity workflows.

## Acceptance Criteria

- [ ] Shared review queue concepts can be modeled without breaking single-user flows.
- [ ] Approval and disposition events are auditable.
- [ ] Team policy controls build on the existing policy engine.
- [ ] Team governance remains out of MVP scope.
