# [FR-001] Workspace Lifecycle Management

## Labels
`MUS`, `enhancement`, `workspaces`

## User Story
As a developer, I want to create, restore, archive, and delete isolated workspaces, so that each agent task has a durable place to run.

## Proposed Solution

### Overview
Implement workspace lifecycle management in `agentd` using git worktrees plus durable metadata in the local TakomiDX state directory.

### Implementation Flow
1. Create a workspace record with stable ID, slug, branch, and filesystem paths.
2. Provision a git worktree from the selected base branch.
3. Persist workspace state so it can be restored after restart.
4. Support archive and delete flows with explicit safeguards.

### Technical Approach

```ts
export interface WorkspaceRecord {
  id: string;
  slug: string;
  branch: string;
  repoPath: string;
  status: "queued" | "ready" | "archived" | "deleted";
}

export interface WorkspaceService {
  create(input: CreateWorkspaceInput): Promise<WorkspaceRecord>;
  restoreAll(): Promise<WorkspaceRecord[]>;
  archive(workspaceId: string): Promise<void>;
  remove(workspaceId: string): Promise<void>;
}
```

### Key Considerations
- Do not corrupt the base repo when archiving or deleting workspaces.
- Keep workspace metadata separate from run metadata.
- Use a stable artifact layout under `.takomi/`.

## Acceptance Criteria

- [ ] A new workspace can be created from a chosen base branch.
- [ ] Workspace metadata is persisted and restored after daemon restart.
- [ ] Archive and delete flows are explicit and safe.
- [ ] The workspace state model is exposed through shared contracts.
