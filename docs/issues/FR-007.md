# [FR-007] VS Code Companion Integration

## Labels
`MUS`, `enhancement`, `editor`

## User Story
As a developer, I want to inspect workspaces from VS Code, so that I can open previews, logs, traces, and approvals without leaving my editor.

## Proposed Solution

### Overview
Create a thin VS Code extension that connects to `agentd`, shows active workspaces, and deep-links into the existing product surfaces.

### Implementation Flow
1. Scaffold the VS Code extension.
2. Connect it to `agentd` using shared contracts.
3. Add a workspace list plus commands for preview, logs, traces, and approvals.
4. Keep the extension focused on discovery and deep links rather than duplicating Mission Control.

### Technical Approach

```ts
export interface WorkspaceListItem {
  id: string;
  name: string;
  status: string;
  previewHost?: string;
}
```

### Key Considerations
- Do not rebuild the full product in the editor.
- Match the naming and status language used by Mission Control.
- Prioritize low-friction navigation.

## Acceptance Criteria

- [x] The extension shows active workspaces from `agentd`.
- [x] Developers can open preview, logs, trace, and approval actions from VS Code.
- [x] Extension terminology matches the core product model.
- [x] The extension remains a thin companion, not a second full control plane.

## Implementation Notes

- Added `apps/vscode-companion` as a VS Code extension package with a dedicated activity bar view and workspace tree.
- Added shared editor companion schemas in `@takomi/contracts` and new read-only `agentd` endpoints under `/api/v1/editor/workspaces`.
- Logs open as editor text documents; preview, trace, validation, and approval surfaces open via VS Code's simple browser against Mission Control or the preview URL.
- Repo and worktree actions reveal the relevant filesystem locations rather than replacing the current VS Code window.
