# [FR-003] Mission Control Dashboard and Workspace Detail Views

## Labels
`MUS`, `enhancement`, `mission-control`

## User Story
As a developer, I want one dashboard for active workspaces, so that I can see status, last action, validation state, and next required action at a glance.

## Proposed Solution

### Overview
Build a web-first Mission Control app with a workspace grid, detail views, activity surfaces, and action-oriented status UI.

### Implementation Flow
1. Create the global Mission Control app shell.
2. Build the workspace grid with filters, state groups, and quick actions.
3. Build the workspace detail views for summary, activity, logs, preview, validation, and trace.
4. Make pending actions and failures obvious above the fold.

### Technical Approach

```tsx
export function WorkspaceCard(props: WorkspaceCardProps) {
  return (
    <article>
      <h2>{props.name}</h2>
      <p>{props.status}</p>
      <p>{props.lastAction}</p>
    </article>
  );
}
```

### Key Considerations
- This should feel like a control plane, not a generic admin dashboard.
- Every alert and notification must carry workspace identity.
- Empty, loading, and failure states matter as much as happy paths.

## Acceptance Criteria

- [ ] Users can see all active workspaces in one grid.
- [ ] Users can open a workspace detail view without losing orientation.
- [ ] Status, last action, preview, and validation state are visible at a glance.
- [ ] Primary actions are available from both grid and detail contexts.
