# [FR-006] Browser-Aware Validation Bundles

## Labels
`MUS`, `enhancement`, `validation`

## User Story
As a developer, I want each workspace to generate validation evidence from a live preview, so that I can review real behavior instead of trusting raw code output.

## Proposed Solution

### Overview
Attach a browser sidecar to each workspace preview and generate validation bundles with screenshots, console diagnostics, network failures, and checklist results.

### Implementation Flow
1. Start a browser sidecar for a workspace preview.
2. Capture browser evidence such as screenshots and console errors.
3. Run a small validation checklist against the live preview.
4. Generate a review bundle for Mission Control.

### Technical Approach

```ts
export interface ValidationBundle {
  workspaceId: string;
  previewUrl: string;
  screenshots: string[];
  consoleErrors: string[];
  checklist: ValidationChecklistItem[];
}
```

### Key Considerations
- The first version should stay deterministic and compact.
- Validation must block false completion states.
- Review bundles should help a human decide, not flood them with noise.

## Acceptance Criteria

- [ ] A workspace can produce a browser-backed validation bundle.
- [ ] Bundles include preview URL, diagnostics, and checklist results.
- [ ] Validation failure prevents a workspace from appearing silently complete.
- [ ] Mission Control can surface the validation bundle clearly.
