# [FR-005] Agent Observability, Spend Visibility, and Policy Controls

## Labels
`MUS`, `enhancement`, `observability`

## User Story
As a developer, I want to see what each agent did, how much it cost, and why it paused or failed, so that I can trust and debug the system.

## Proposed Solution

### Overview
Define a canonical event model for agent runs, emit structured events and spans, and layer policy hooks on top for budgets, loop detection, and approval gates.

### Implementation Flow
1. Define workspace, run, tool, auth, preview, and validation event contracts.
2. Emit structured events from `agentd` services.
3. Summarize tokens, spend, and run state for Mission Control.
4. Add policy evaluation for budgets, repeated failures, and risky actions.

### Technical Approach

```ts
export interface AgentEvent {
  workspaceId: string;
  runId: string;
  type: string;
  timestamp: string;
  summary?: string;
}

export interface PolicyDecision {
  action: "allow" | "warn" | "pause";
  reason: string;
}
```

### Key Considerations
- Use shared contracts so observability stays portable.
- Stop reasons and pause reasons should be structured, not buried in logs.
- The first iteration should optimize for clarity, not analytics depth.

## Acceptance Criteria

- [x] Runs emit structured lifecycle and tool events.
- [x] Mission Control can show last action, cost, and pause reason.
- [x] Budget exceed events can warn or pause a run.
- [x] Repeated-failure loops can be detected and surfaced.
