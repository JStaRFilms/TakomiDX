# [FR-004] Local Auth Broker for Workspace-Safe OAuth

## Labels
`MUS`, `enhancement`, `auth`

## User Story
As a developer, I want auth callbacks to resolve to the correct workspace regardless of runtime port, so that login flows do not break during concurrent local development.

## Proposed Solution

### Overview
Implement a stable local auth broker that receives callbacks on one fixed local surface, validates signed state, and routes the result to the correct workspace.

### Implementation Flow
1. Start an auth broker service on a stable hostname.
2. Issue signed state values bound to a workspace and nonce.
3. Receive provider callbacks and validate the state.
4. Forward the result to the correct workspace and surface errors to Mission Control.

### Technical Approach

```ts
export interface AuthSession {
  id: string;
  workspaceId: string;
  provider: string;
  status: "requested" | "callback_received" | "completed" | "failed";
}

export interface AuthBroker {
  createSession(input: CreateAuthSessionInput): Promise<AuthSession>;
  handleCallback(input: AuthCallbackInput): Promise<AuthSession>;
}
```

### Key Considerations
- Never log raw tokens.
- State validation must be strict.
- Device flow support should exist for tool-oriented auth where redirects are undesirable.

## Acceptance Criteria

- [ ] OAuth callback routing does not depend on random runtime ports.
- [ ] The auth broker validates signed state and workspace binding.
- [ ] Redirect mismatch and invalid state failures surface clearly.
- [ ] Workspace auth state is visible to the UI as structured status.
