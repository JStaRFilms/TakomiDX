# [FR-008] Replayable Run Journal

## Labels
`Future`, `enhancement`, `replay`

## User Story
As a developer, I want to replay prior agent runs, so that I can understand failures and resume from known checkpoints.

## Proposed Solution

### Overview
Extend the event model into a replayable run journal with checkpoints, run reconstruction, and operator-friendly postmortem playback.

### Implementation Flow
1. Persist a canonical append-only run journal.
2. Snapshot key checkpoints and externalized artifacts.
3. Reconstruct prior runs for replay and analysis.
4. Add UI support for stepping through a prior run.

### Technical Approach

```ts
export interface RunJournalEntry {
  runId: string;
  sequence: number;
  type: string;
  payload: unknown;
}
```

### Key Considerations
- Storage growth must be controlled.
- Sensitive data must be redacted or excluded.
- Replay quality depends on disciplined event design in the MVP.

## Acceptance Criteria

- [ ] Run journal entries can be persisted in sequence.
- [ ] A prior run can be reconstructed from stored journal data.
- [ ] Sensitive values are not exposed in replay artifacts.
- [ ] The replay model is additive and does not destabilize MVP flows.
